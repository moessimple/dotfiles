# Sync Skeleton

- The project was bootstrapped from `moessimple/laravel-starter-kit` and then
  customised. The user owns the code.
- We pull the kit's **quality gate and tooling config** (PHPStan, Pint, Rector,
  Pest config, CI, vite-plus, Essentials config), not app code and not features.
- The project's git history is unrelated to the kit's. There is no common
  ancestor. We compare project-now vs `origin/<default-branch>`-now, byte by byte.
- Scope is a fixed list: `scripts/gate-paths.txt` plus the two manifests. We
  never walk the whole tree.
- We never auto-merge a customised file. Differences are surfaced; the user
  decides. Taking the kit's version is the recommended default for gate config,
  but it is still per file and still vetoable.
- **Behavior preservation is the contract**: the checks that pass before the
  sync must still pass after. A stricter finding the newly-synced gate surfaces
  in *app code* is a follow-up, not a regression.

Invocation: `/sync-skeleton [target]`. `target` defaults to the git toplevel of
the current directory.

## Safety contract: non-negotiable

Read these to the user before any side effect, and live by them throughout.

1. Working tree must be clean. If `git status --porcelain` is non-empty, refuse
   and tell the user to commit or stash. Never stash for them.
2. All work happens on a dedicated branch, `sync-skeleton/<yyyymmdd-hhmm>-<slug>`.
   The user's current branch is never modified.
3. Each applied group is its own commit. That is how revertability works.
4. Never auto-resolve a conflict. A `differs` file is surfaced with the diff;
   if the user is unsure twice, keep their copy and move on.
5. Never silently overwrite a manifest or lockfile. `composer.json` /
   `package.json` change only through the `plan-manifest.sh` directives and the
   script-alias realignment; lockfiles are regenerated by their tool.
6. Verify behavior preservation. Record a baseline with `run-tests.sh` before,
   compare after. A check that passed in the baseline and fails now is a
   regression: stop, surface it, recommend `git revert`. Do not patch to green.
7. Detect from unambiguous signals; ask when ambiguous. Do not guess.

If any of these cannot hold, abort with a clear message about what went wrong
and how to recover.

## Required tools

- `git` in the project. Required.
- `bash` for the bundled scripts. No `jq`.
- `composer` and the project's JS package manager, for Phase 6. If absent,
  Phase 6 reports what it could not regenerate instead of failing the run.
- `gh` optional, only to enrich commit titles. Fall back to `git log`.

## Gotchas

Read before starting; apply throughout.

- **Monorepo sub-package.** A project like `tinkerbench` has `packages/runner`
  with its own `composer.json` and gate. The kit knows nothing about it. When
  realigning a script alias, align the base to the kit and **append** the
  project's `--working-dir=packages/runner` fan-out; never drop it.
- **eslint/prettier to vite-plus.** The kit dropped eslint and prettier for
  vite-plus. `plan-manifest.sh` emits `remove npm` directives and `classify.sh`
  marks the config files `deleted-upstream`. Applying this is a toolchain swap:
  do the mechanical part (remove the family, add vite-plus, rewrite the
  `package.json` gate scripts, delete the config files), then list every
  `eslint-disable` / `prettier-ignore` / `@/lib/utils` hit in `resources/**` as
  an app-code follow-up. Whether `vp lint` then passes is the user's problem.
- **PHP 8.5 / Node 24.** The kit requires them. If the project is behind,
  `composer update` may refuse to resolve and the 100% coverage gate cannot run
  locally. Note it, carry on; CI still enforces it.
- **Herd-injected setup lines.** The project's `composer setup` alias may carry
  `herd link` / `herd isolate` lines. Keep them when realigning; they are the
  project's, not drift.
- **`roave/security-advisories` (dev-latest).** Once a dependency has a known
  advisory it blocks the next `composer update`. Expected; name what it blocks.
- **Essentials wiring.** `config/essentials.php` syncs as a gate file, but
  `nunomaduro/essentials` in `require` and the `bootstrap/app.php` wiring are
  never-touch. List them as follow-ups.
- **More than ~40 `differs`.** The per-file walk stops being useful. Recommend a
  manual pass for the gate and skip the walk.
- **Framework majors.** A Laravel or Inertia major jump is not this skill. Point
  the user at the relevant Laravel Boost upgrade command, then re-run this skill
  against the clean-tree result.

## What is in scope

- **Gate paths**: everything in `scripts/gate-paths.txt` (split CI, `phpstan.neon`,
  `rector.php`, `pint.json`, `.gitattributes`, `phpunit.xml`, the vite/vitest/
  tsconfig/npm tooling files, `config/essentials.php`). `classify.sh` also flags
  any kit path at the repo root or under `.github/` that the list omits as
  `ungrouped`; adopt it in the Phase 5 walk, and add it to the list if it should
  sync automatically from then on.
- **Manifests (guided)**: `composer.json` `scripts` + `require-dev`, `package.json`
  `scripts` + `devDependencies`, via `plan-manifest.sh` and script realignment.
  Runtime `require` / `dependencies` are shown, never written.
- **`deleted-upstream`**: `eslint.config.*`, `.prettierrc*`, `.prettierignore`,
  `resources/js/lib/utils.ts`. Keep by default; delete as part of the vite-plus
  migration when the user opts in.

Not in scope, never touched: `app/**`, `database/**`, `routes/**`, `bootstrap/**`,
`config/**` except `config/essentials.php`, `tests/**` (the arch/browser suites
are a separate concern), `.ai/**` and `.claude/**` agent rules, the Welcome page,
`.gitignore` / `.env.example` / `CLAUDE.md` (drift shown, never written).

## Workflow

Six phases, in order. Each establishes what the next relies on.

### Phase 1: Preflight and detect

```
scripts/preflight.sh laravel-starter-kit <target>
```

Surface its message verbatim; stop on any non-zero exit (1 not-a-repo, 2 dirty,
3 not-a-descendant, 64 bad args).

Check the environment against the kit README and record it for the report: PHP
`>= 8.5` (`php -v`), Node `>= 24` (`node -v` vs `.nvmrc`), a coverage driver
(Xdebug or PCOV, `php -m`). A mismatch is a note, not a stop.

### Phase 2: Fetch and classify

```
kit_line=$(scripts/fetch-kit.sh laravel-starter-kit)   # <kit_dir>\t<branch>\t<sha>
scripts/classify.sh    laravel-starter-kit <kit_dir> <branch> <target>
scripts/plan-manifest.sh laravel-starter-kit <kit_dir> <branch> <target>
```

Hold the kit SHA for the commit messages and the report.

### Phase 3: Present and select

Group the `classify.sh` output for the user:

- `new` files: default **apply**.
- `differs` files: default **walk one by one** (Phase 5). List them with a
  changed-line count so the user sees the size.
- `deleted-upstream`: default **keep**. If `plan-manifest.sh` emitted
  `remove npm` for an eslint/prettier family, offer the **vite-plus migration**
  as one opt-in step that also deletes these.
- `ungrouped`: always show. The kit added a gate file `gate-paths.txt` does not
  list; add it before finishing.
- `already-present`: silent.
- `plan-manifest.sh` directives (`add` / `align` / `remove`): show them. `align`
  can move a constraint *backwards* to the kit's floor; call that out.

Also show, never write: the diff for `.gitignore`, `.env.example`, `CLAUDE.md`.

If every gate path is `already-present` and `plan-manifest.sh` prints nothing,
the gate already matches the kit: say so and stop. No branch, no empty commit.

Wait for the selection. Recap the picks and counts. Confirm once more before any
side effect.

### Phase 4: Baseline and workspace

```
baseline=$(mktemp "${TMPDIR:-/tmp}/sync-skeleton-baseline.XXXXXX")
scripts/run-tests.sh <target> --baseline "$baseline"
```

`run-tests.sh` records the PHP suite plus, when `package.json` has them, the JS
typecheck and JS build. Hold `$baseline`; Phase 6 compares against it. If a check
is red already, note it in the report; Phase 6 only flags checks that were green
and turn red.

```
git -C <target> switch -c "sync-skeleton/$(date +%Y%m%d-%H%M)-<first-slug>"
```

If the user is already on a `sync-skeleton/...` branch, do not delete it. Ask
whether to resume on it, start fresh, or abort. From here every write goes to
this branch.

### Phase 5: Apply

1. **New files.**

   ```
   scripts/apply-new-files.sh laravel-starter-kit <kit_dir> <branch> <target>
   ```

   Before running, the rename check: if a `new` path's basename already exists
   elsewhere in the project, surface it, do not auto-apply. After, scan the
   written files for imports of helpers the project may lack:

   ```
   scripts/scan-imports.sh <applied_files...>
   ```

   Each `<file>:<line>:<match>` whose target is missing is a follow-up
   dependency; do not book the group as done.

2. **Walk `differs`, `deleted-upstream`, `ungrouped`.** One file at a time: show
   the kit version (`git -C <kit_dir> show origin/<branch>:<path>`), the project
   version, and the diff (`/usr/bin/diff -u` or
   `git --no-pager diff --no-index`, never the `diff` alias). The user picks:
   take the kit version wholesale (confirm), keep theirs, or merge by hand.
   Unsure twice: keep theirs, move on. Stage the choice.

3. **Manifests.** Apply the `plan-manifest.sh` directives the user approved
   (`composer require --dev` / `composer remove --dev` and the JS equivalent, so
   `composer.json`/`package.json` and their locks move together). Then realign
   the kit's script aliases (`setup`, `dev`, `lint`, `test:lint`, `test:types`,
   `test:type-coverage`, `test:unit`, `test:browser`, `test`,
   `update:dependencies`; `build`, `build:ssr`, `dev`, `lint`, `test:lint`,
   `test:unit`, `test:types` in `package.json`) to the kit's bodies, appending
   only genuine project additions (the monorepo fan-out). Flag every realignment
   for veto. `setup` matters because that is where the kit runs
   `npx playwright install chromium`.

   **vite-plus migration** (only when selected in Phase 3): the `deleted-upstream`
   config files are removed here; rewrite the `package.json` gate scripts to the
   kit's bodies; scan `resources/**` for `eslint-disable` / `prettier-ignore` /
   `@/lib/utils` / a bare `cn(` and list every hit as an app-code follow-up.

4. **Commit.** One commit per group (`sync-skeleton: gate config`,
   `sync-skeleton: manifests`). Message names the kit SHA and, per file, the
   decision (added / took-upstream / manual-merge / kept).

### Phase 6: Reconcile, verify, report

1. **Lockfiles.**

   ```
   scripts/reconcile-manifests.sh <target>
   ```

   Commit as a separate `sync-skeleton: dependency lockfiles` commit.

2. **Browser runtime.** When `pest-plugin-browser` is now in `require-dev` and
   `tests/Browser/Pest.php` is present, run `npx playwright install chromium`
   (one-time, downloads a browser, not a repo change; confirm first). Do not run
   the full `composer setup` (it also runs `migrate --force`). If it fails, list
   it as a prerequisite.

3. **Behavior preservation.**

   ```
   scripts/run-tests.sh <target> --compare "$baseline"
   ```

   Three checks: the PHP suite, and (when `package.json` carries the scripts) the
   JS typecheck and the JS build. The PHP baseline runs the low-level suite
   (`vendor/bin/pest` / `phpunit`), not `composer test`, so realigning the `test`
   alias in Phase 5 does not by itself turn the comparison red. Compare re-runs
   each command the baseline recorded and prints `REGRESSION` only for a check
   that was `pass` before and `fail` now. Any such line: stop, show the log it
   points to, recommend `git revert <group-sha>`; if uncertain which group,
   `git bisect start <branch> <previous>`. Do not edit code to go green.

   If the Phase 1 environment check found PHP, Node, or the coverage driver short
   of the kit's requirement, the 100%-coverage and type-coverage gates cannot run
   locally. Record the result as `NOT-VERIFIED-LOCALLY: <what was missing>` and
   say so at the top of the report; do not imply verification passed. CI still
   enforces it.

   The synced gate is stricter than this preservation check, so run the *full*
   `composer test` once more and copy its output verbatim into the report as the
   app-code to-do list. Findings there are follow-ups, not regressions.

4. **Report.** Write to `${TMPDIR:-/tmp}/sync-skeleton-report-<id>.md` (`<id>`
   matches the branch's `sync-skeleton/<id>`). Show the path; ask whether to copy
   it into the project. Sections:

   ```markdown
   # Sync Skeleton Report

   - Date / kit SHA / branch / environment check

   ## Applied
   - <group>: added <list>, took upstream <list>, manual merge <list>, kept <list>

   ## Manifests
   - directives applied / vetoed; script aliases realigned; vite-plus migration; lockfiles

   ## Verification
   - environment: PHP <version> / Node <version> / coverage driver <yes|no>
   - baseline vs compare: PASS / REGRESSED <list> / NOT-VERIFIED-LOCALLY <reason> / NO-CHECKS
   - full gate (`composer test`) output: <verbatim, the app-code to-do list>

   ## Follow-ups (not done by this skill)
   - npx playwright install chromium (if it could not run)
   - nunomaduro/essentials in require + bootstrap/app.php wiring
   - tests/Pest.php wiring; .gitignore / .env keys; strict-types / coverage on app code

   ## How to revert
   - one group: `git revert <sha>`
   - everything: `git switch <previous> && git branch -D sync-skeleton/<id>`
   ```

## Out of scope

- Detecting which kit version the project started from.
- Resolving runtime dependency constraints. Shown only.
- The reverse direction (project into kit).
- Running linters or formatters on applied files.
- App code, DB migrations, routes, `bootstrap/**`, domain tests, agent rules.
